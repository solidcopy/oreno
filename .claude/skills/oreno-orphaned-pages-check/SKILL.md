# 孤立ページチェック

`/index` からリンクを辿ってもたどり着けないページ(孤立ページ)を探して一覧にする画面。リンクの解釈はリンク切れチェックと共通なので、リンクの扱いの詳細は oreno-link-broken-check スキルを参照する。

## 画面の仕様

- メニュー名と画面タイトルは「孤立ページチェック」。アプリメニューの「リンク切れチェック」の下に置く。URLは `/.oreno/orphaned_pages_check`
- 画面を開くたびに、毎回チェックを実行する。結果は保存もキャッシュもしない
- 画面を離れたら、チェックを中断する
- この画面自体は閲覧履歴に記録しない
- ページのパスのリンクは、通常のページ移動と同じ。表示モードか編集モードかは、ユーザー設定に保存されているモードに従う(この画面では指定しない)

### チェック中

進捗率や残り時間は出さない。動画のバッファリング中のように、3つの点が順に跳ねる表示と「孤立ページチェック中です…」「/indexからリンクで辿り着けないページがないか調べています。完了すると結果が表示されます。」を出す。カードは出さない。OSで動きを減らす設定のときは、点を動かさない。

### 完了後

- 孤立ページがあるときは、「チェック完了: n件の孤立ページが見付かりました」の件数行と、孤立ページのカードを出す
- 孤立ページがないときは、「孤立ページは見付かりませんでした」を出す
- チェック自体に失敗したときは「チェックに失敗しました。」を出す
- ライトモード・ダークモードの両方に対応する(OSの設定に従う)

### カード

- 孤立ページ1件につきカード1枚。並び順は決めず、見付けた順(フォルダの走査順)
- カードにはページのパス(そのページへのリンク)と、ページの最初の5行を出す
- 行の表示はテキストエディタのように、左に行番号だけの欄を置き、垂直の境界線で本文と区切る。リンク切れチェックのカードと同じ見た目で、強調表示はしない
- 空行も行として数える。ページが5行に満たなければ、ある行だけを出す。末尾の改行の後ろには空行があるとは数えない
- 空のページは、行番号の欄を出さず、ページのパスだけのカードにする。「（空のページ）」のような表示はしない

## 孤立の判定

実装は `src/lib/orphanedPagesCheck.ts` の `findOrphanedPages`。

- `/index` を出発点に、リンクを辿って到達できたページの集合を求める(幅優先)。文書ルート以下のページのうち、集合に入らなかったものが孤立ページ
- サイドバー(ページ一覧、スター付き、履歴)からアクセスできるかどうかは、判定に含めない
- ページ同士が互いにだけリンクしていて、`/index` から辿れない場合も、どちらも孤立とする。自分自身へのリンクだけがあるページも同様
- `/index` 自身は出発点なので孤立ページにならない。`/index` が存在しなければ、すべてのページが孤立ページになる
- リンクの解釈(検査対象の記法、外部URLや `#見出し` の扱い、相対リンクの解決、ドット始まりのパス)は、リンク切れチェックと同じ。`src/lib/pageLinks.ts` の `extractLinks` と `resolveLinkTarget` を共通で使う
- リンク先がページ(`〜.md`)として存在するときだけ辿る。画像など、Markdown以外のファイルへのリンクは辿らない。ルートURL(`/`)へのリンクは `/index` へのリンクとして扱う
- 対象のページと走査のルール(`.` から始まる名前を除く、URLにできない名前のページを除く)は、リンク切れチェックと共通の `src/lib/walkPages.ts` の `walkPages`

## 実装の仕組み

- 画面(`page.tsx` と `OrphanedPagesCheckPage.tsx`)はチェックを実行しない。画面が開いてから、`useEffect` で Route Handler(`check/route.ts`)へ `fetch` する。Server Actionにしない理由と中断の仕組みは、リンク切れチェックと同じ(oreno-link-broken-check スキルを参照)
- 中断は、フォルダを辿る `walkPages` の冒頭と、リンクを辿る繰り返しの中、孤立ページを読む繰り返しの中の `signal.throwIfAborted()` で止まる
- ファイル一覧(ファイルインデックス、oreno-file-index スキル)は使わない。画面を開いたときに独自にフォルダを辿る
- 到達できたページは、リンクを調べるため全文を読む。孤立ページは、カードに出す先頭の数行のためだけに最後に読む(現状は全文を読んでから先頭5行を切り出している)
- チェック中に文書が編集・作成・削除されても、結果に反映されるかどうかは決めていない(実装が簡潔な方でよい)
