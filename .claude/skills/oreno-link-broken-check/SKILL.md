# リンク切れチェック

文書ルート以下のすべてのページから、存在しないページやファイルへのリンクを探して一覧にする画面。

## 画面の仕様

- メニュー名と画面タイトルは「リンク切れチェック」。アプリメニューの「すべてのページ」の下に置く。URLは `/.oreno/link_broken_check`
- 画面を開くたびに、毎回チェックを実行する。結果は保存もキャッシュもしない
- 画面を離れたら、チェックを中断する
- この画面自体は閲覧履歴に記録しない。履歴の記録は `DocumentPage.tsx` が文書の表示時にだけ行うため、特別な処理は要らない
- ページのパスのリンクは、通常のページ移動と同じ。表示モードか編集モードかは、ユーザー設定に保存されているモードに従う(この画面では指定しない)

### チェック中

進捗率や残り時間は出さない。動画のバッファリング中のように、3つの点が順に跳ねる表示と「リンクチェック中です…」「リンクの整合性を調べています。完了すると結果が表示されます。」を出す。カードは出さない。OSで動きを減らす設定のときは、点を動かさない。

### 完了後

- エラーがあるときは、「チェック完了: N件のエラーが見付かりました」の件数行と、リンク切れのカードを出す
- エラーがないときは、「エラーは見付かりませんでした」を出す
- チェック自体に失敗したときは「チェックに失敗しました。」を出す
- ライトモード・ダークモードの両方に対応する(OSの設定に従う)

### カード

- リンク切れ1件につきカード1枚。同じページに複数あれば、その数だけカードを出す。並び順は決めず、見付けた順(フォルダの走査順、ページ内は出現順)
- カードにはページのパス(そのページへのリンク)と、リンクのある行を出す。「リンクが切れています」のような文言は出さない(この画面のカードはリンク切れしかないため)
- 行の表示はテキストエディタのように、左に行番号だけの欄を置き、垂直の境界線で本文と区切る
- 文字数で切らず、リンクのある行全体を出す。リンクが複数行にまたがるときは、すべての行を出す(行ごとに行番号を付ける)
- 行の中のリンク部分(`[文字](URL)` の記法全体)は強調表示する

## 検査の対象

- Markdownのページのみ。フォルダは、文書ルートから再帰的にすべて辿る
- `.` から始まる名前のフォルダ・ファイルは辿らない。URLにできない名前のページも調べない(`resolveDocPath` で検証する)
- 検査するのは、リンク `[文字](URL)`、画像 `![代替文](URL)`、リンク定義 `[名前]: URL` のURL。リンク定義は、リンク参照 `[文字][名前]` 自身がURLを持たないため、定義の行を検査する
- 本文中に直接書かれたHTML(`<a href>` など)は対象外。コードブロックの中に書かれたリンク風の文字列も対象外(構文木で解釈するため)

## 存在判定のルール

リンク先の解決は `src/lib/pageLinks.ts` の `resolveLinkTarget`(孤立ページチェックと共通)、存在の判定は `src/lib/linkBrokenCheck.ts` の `isBroken`。

- 外部URL(`https://` や `mailto:` などスキーム付き、`//` 始まり)は調べない
- `#見出し` と `?クエリ` は取り除き、パス部分だけで判定する。取り除いた結果が空(`#見出し` だけなど、同じページ内を指すリンク)なら調べない。見出しが実際にあるかは見ない
- パスはパーセントデコードしてから判定する。デコードできないものは切れ扱い
- 相対リンクは、ブラウザと同じく、リンクのあるページが置かれているフォルダを基準に解決する。`/` 始まりは文書ルートが基準。文書ルートより上へ出る `..` は切れ扱い
- 解決後のパスが空(ルートURL)なら、`/index` へのリダイレクトがあるので正常扱い
- `/.oreno/...` はOreno自身の画面なので、存在を調べず正常扱い。それ以外の `.` 始まりのセグメントを含むパスは、ドット始まりのパスが存在しないものとして扱われる(oreno-file-routing スキル)のに合わせて切れ扱い
- 存在の判定は oreno-file-routing スキルの順と同じ。まず `〜.md` のファイルを、なければ同名のファイルを探す。フォルダだけが存在する場合は切れ扱い
- 同じリンク先は一度しか調べない(1回のチェックの中でキャッシュする)

## 実装の仕組み

- 画面(`page.tsx` と `LinkBrokenCheckPage.tsx`)はチェックを実行しない。画面が開いてから、`useEffect` で Route Handler(`check/route.ts`)へ `fetch` する
- Server Actionにしないのは、実行中のServer Actionは途中で中断できないため。Route Handlerなら、画面を離れたときの `AbortController.abort()` でブラウザがリクエストを打ち切り、サーバー側の `request.signal` に伝わる。調査は、フォルダを辿る `walkPages`(`src/lib/walkPages.ts`、孤立ページチェックと共通)の冒頭の `signal.throwIfAborted()` で止まる
- ファイル一覧(ファイルインデックス、oreno-file-index スキル)は使わない。インデックスは10分周期のスキャンで最新でないことがあるため、画面を開いたときに独自にフォルダを辿る
- チェック中に文書が編集・作成・削除されても、結果に反映されるかどうかは決めていない(実装が簡潔な方でよい)。今は、各ページを読んだ時点の内容で検査する
