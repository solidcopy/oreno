# プロジェクト設定

プロジェクト(文書セット)単位の設定は `(ORENO_ROOT)/.oreno/project-settings.json` に保存する。文書セットと一緒にGit管理して共有する設定が対象で、ユーザーごとの設定(`user-settings.json`。oreno-user-settings スキルを参照)とは別ファイルにしている。読み書きは `src/lib/projectSettings.ts` に集約しており、設定を追加するときもここに足す。

## 設定項目

| JSONのキー | アプリ内の名前 | 内容 |
| --- | --- | --- |
| `project-name` | `projectName` | プロジェクト名(文字列)。未設定は空文字 |
| `image-folders` | `imageFolders` | 画像をインポートするときのコピー先として選べるフォルダの配列。`"/images"` のような絶対形式の文字列で、未設定は空の配列 |

ファイル内のキー名はケバブケースで、アプリ内の名前との変換は `projectSettings.ts` に閉じ込める。

## ファイルの扱い

- ファイルが無い場合、JSONとして解析できない場合は、エラーにせず未設定扱いにする(それ以外の読み込みエラーは例外のまま)
- 値の型が想定と違う項目は、その項目だけ未設定扱いにする。`image-folders` は、配列でなければ空の配列とし、文字列以外の要素は無視する
- 保存は、すべての項目をまとめて書き直す。ユーザー設定のように「更新するキーだけを差し替える」方式ではないので、項目を追加したら `saveProjectSettings` が新しい項目も書き出すようにする(書き忘れると、保存のたびにその項目が消える)
- 保存時に `git commit` は行わない(oreno-deployment スキルの方針どおり)

## プロジェクト名の表示

プロジェクト名はヘッダーのリンクなどに全ページ共通で表示する。表示では20文字を超える分を省略し、19文字目までの末尾に「...」を付ける(`src/lib/projectNameDisplay.ts`)。入力自体に文字数制限は設けない。

## プロジェクト設定画面

`/.oreno/project_settings` で、プロジェクト名と画像フォルダ一覧を編集する。実装は `src/app/.oreno/project_settings/`(`page.tsx` が設定を読み、`ProjectSettingsPage.tsx` が画面、`actions.ts` が保存のServer Action)。

- 「設定を保存する」を押すまでは、入力は画面上の状態だけで、設定ファイルにも他のページにも反映しない
- 保存に成功したら「設定を保存しました。」を3秒表示し、失敗したらメッセージを画面に出す
- 保存したら `revalidatePath("/", "layout")` で全ページの描画結果のキャッシュを破棄する。プロジェクト名が全ページのヘッダーに出るため、これがないと戻る/進むで古い名前が表示される
- Server Action は誰でも直接POSTできるため、保存時にも `image-folders` の各パスを検証する。`normalizeFolderPath` で整えても変わらない(すでに絶対形式に整っている)パスだけを受け付け、ひとつでも不正なら保存せずに「画像フォルダのパスが正しくありません。」を返す

### 画像フォルダ一覧

プロジェクト名の下に置く。見出しは「画像フォルダ一覧」で、その下に小さい文字で次の注意書きを、文ごとに改行して表示する。

> 一覧のフォルダは画像をインポートする際にコピー先のフォルダとして選択することができます。
> 一覧にないフォルダも直接パスを入力すれば画像を保存できます。

- 追加欄: フォルダのパスを入力する。入力中は、文書セット内の既存フォルダを候補としてドロップダウンに表示する(`src/components/FolderPathInput.tsx`)。候補の絞り込み・並び順・キー操作はリンク先の候補と同じで(oreno-editor-ui スキルの `references/link.md`)、違いは候補がフォルダだけである点。候補は、ファイルインデックス(oreno-file-index スキル)のファイル一覧から、各ファイルの祖先フォルダを集めて作る(`listFolders`)。存在しないフォルダも、直接入力すれば追加できる
- 追加欄の右の「追加」ボタン(Enterキーも同じ)で、入力したフォルダを一覧の末尾に追加し、追加欄を空にする。追加できないときは、理由を追加欄の下に表示し、入力を変えると消す
  - パスが使えないとき(空欄、`/` だけ、`/images//` のような空の名前を含む、`.` から始まる名前を含む、`:` や `[` などURLのセグメントとして許可しない文字を含む): 「フォルダのパスが正しくありません。」
  - すでに一覧にあるとき: 「すでに一覧にあります。」
- 入力は絶対形式に整えてから扱う(`normalizeFolderPath`)。先頭に `/` が無ければ補い、先頭・末尾の `/` 1つと前後の空白は取り除く。`images` も `/images/` も `/images` になる。`//` が続く(空の名前がある)パスは、整えずに不正として扱う
- 一覧: 5件分の高さで、それ以上はスクロールする。標準の `<select size="5">` を使う。1件だけ選択できる(複数選択はできない)
- 一覧の下の「削除」ボタンで、選択中のフォルダを一覧から削除する。選択していないときは押せない
- 未選択のときは、一覧のどの項目も選択状態にしない。`select` に `value` を渡すと、一致する項目がないとき React が先頭の項目を選択状態にしてしまい、削除ボタンが押せないのに選択されて見えるため、`value` は渡さず、`useEffect` で `selectedIndex` を -1 にしている

### 画像インポートでの使い道

一覧のフォルダは、画像インポートモーダルの画像フォルダ選択ボタンの選択肢になる(「（ページのフォルダ）」の次に、一覧の順に並べる)。この機能は未実装で、画像のドロップは現在、確認なしでページと同じフォルダへコピーしている(oreno-editor-ui スキルの `references/image.md`)。
