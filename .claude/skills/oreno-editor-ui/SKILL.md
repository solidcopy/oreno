# 表示モードと編集モード

リクエストされた文書は、ユーザー設定のモード(`mode`。仕様は oreno-user-settings スキルを参照)で表示する。未設定のときは読み取り専用の表示モードで開く。

- 表示モードでは「編集モードに切り替え」ボタンとその右に「削除」ボタンを表示する。「編集モードに切り替え」を押すと編集可能になる
- 編集モードでは「新規作成」ボタン(「表示モードに切り替え」の左。動作は表示モードと同じ)、「表示モードに切り替え」ボタン、「削除」ボタンを表示する。新規作成中(ファイルが存在しないとき)は「新規作成」を表示しない。「表示モードに切り替え」を押すと、保存待ちの編集があれば先に保存してから表示モードにする。保存に失敗したときは、編集が失われないよう編集モードのままにする
- 2つのモード切り替えボタンは、同じ幅で表示する
- 「移動」ボタンを、モード切り替えボタンと「削除」の間に表示する(新規作成中は表示しない)。表示中のページの.mdファイルを移動またはリネームする。押すと「新規作成」と同じ形のポップアップで移動先のパスを入力する。ラベルは「移動するページのパス」、実行ボタンは「移動」。パスの扱い(`.md` の付与、フォルダの自動作成、空欄・`.` から始まる名前を含むパス・既存ファイルのエラーメッセージ)は新規作成と同じ。移動できたら移動先のページへ遷移する。編集モードでは移動の直前に保存待ちの編集を保存し、保存に失敗したら移動しない。移動したら、閲覧履歴とスター付きページに記録されている移動元のパスも移動先に付け替える(`renamePageInSettings`。移動先がすでに記録されていれば重複させない。付け替えに失敗しても移動は成功扱い)
- 「削除」を押すとファイルを削除する(確認ダイアログを出す)。削除したあとは、下記の新規作成の画面と同じ状態になる
- モードを切り替えるたびに、ユーザー設定の `mode` へ保存する(ページを移動したりリロードしても変わらないようにするため)

# 編集内容の自動保存

編集モードでは、編集内容を自動的にファイルへ保存する。「保存」ボタンはない(新規作成を除く。次節を参照)。

- 最後の編集から0.5秒、追加の編集がなかったときに保存する(1文字ごとに保存しないため)
- 日本語入力などの変換中(未確定)は保存しない。確定したあとに保存する
- ヘッダーの現在ページのパスの右に、保存の状態を表示する(`Header.tsx` の `saveStatus`)
  - 保存待ちまたは保存中: （保存中...）をやや目立たない色で表示する
  - 保存に失敗した: （保存失敗）を赤で表示する。メッセージが消えたあとも保存できていないことが分かるようにするため
  - 保存に成功した: （保存済み）を（保存中...）と同じ色で表示する。次の編集で（保存中...）に変わるまで、そのまま表示し続ける
  - ページを開いてからまだ編集していない間は何も出さない
- 保存に失敗したときは、画面上部に「文書の保存に失敗しました。」を赤い背景で表示し、ユーザー設定画面の保存通知と同じ3秒で消す
- 失敗しても自動では再試行しない。次に編集したときに改めて保存を試みる
- アプリ内で別のページへ移動するときは、保存待ちの編集を待たずに、移動の直前の内容を今すぐ保存する。ブラウザのタブを閉じる場合は対象外(保存できないことがある)
- 保存の途中でさらに編集されたときは、その編集の保存が改めて走る。保存済みの内容と同じになったとき(編集して元に戻したときなど)は保存しない
- 保存に使う Server Action のボディサイズ上限は、`next.config.ts` の `serverActions.bodySizeLimit` で10MBにしている(デフォルトの1MBでは大きな文書が保存できないため)

# ページの新規作成

存在しないファイルを参照するURLにアクセスすると、ユーザー設定の `mode` に関わらず編集モードで空の文書を開く(404にはしない。404になるのはURL自体がファイルパスに対応できない場合のみで、これはoreno-file-routingスキルの管轄)。このときユーザー設定の `mode` は更新しない。

新規作成では、自動保存はしない。

- ヘッダーのパスの右に、（保存中...）の代わりに（新規）を表示し、その右に「保存」「キャンセル」ボタンを表示する(`saveStatus` が `"new"`)
- 「保存」を押すと、URLに対応するMarkdownファイルを新規作成する。保存したあとのモードは、ユーザー設定の `mode` に従う。保存に失敗したときは、新規作成の画面のまま、自動保存の失敗と同じメッセージを表示する
- 「キャンセル」を押すと、直前まで表示していたページに戻る(ブラウザの戻る)。履歴がなく戻れないときは `/index` へ移動する
- 保存の途中は、「保存」「キャンセル」を押せないようにする
- 入力した内容は、保存せずにページを移動すると失われる

# 下線の文字修飾

編集モードでは、文字に下線を引ける。Markdownファイルの中ではHTMLの `<u>…</u>` として保存する。

- テキストを選択すると出るツールバーの、取り消し線の右にある「U」ボタンで下線を引く(もう一度押すと外す)
- ショートカットは Mod+U
- `__テキスト__` と入力すると下線になる(Milkdown標準では太字になるが、下線を優先している)。`**テキスト**` は従来どおり太字
- 実装は `src/components/underlinePlugin.ts`。読み込み時に対になる `<u>` と `</u>` を1つのマークにまとめ、対応する `</u>` がない `<u>` はHTMLのまま残す
- 表示モードでは `rehype-raw` で `<u>` を要素として解釈する。`<u>` 以外の生HTMLは従来どおり `rehype-sanitize` が取り除く(`src/lib/markdown.ts`)

# 上付き・下付きの文字修飾

編集モードでは、文字を上付き・下付きにできる。Markdownファイルの中ではHTMLの `<sup>…</sup>`(上付き)と `<sub>…</sub>`(下付き)として保存する。

- テキストを選択すると出るツールバーの、下線の右にある「上付き」「下付き」ボタンで設定する(もう一度押すと外す)
- ショートカットと、Markdown入力からの自動変換は用意していない
- 上付きと下付きは同時に付けられない。片方を付けると、もう片方は外れる
- 上付き・下付きの直後に続けて入力した文字には、マークが付かない(修飾なしの文字になる)。太字や下線は、直後に入力した文字にも同じ修飾が付く
- 実装は `src/components/scriptPlugin.ts`。下線(`underlinePlugin.ts`)と同じ仕組みで、対になる開きタグと閉じタグを1つのマークにまとめる
- 表示モードでは、`<sup>` `<sub>` は `rehype-sanitize` の既定で許可されているため、追加の設定なしで表示される

# 数式(LaTeX)の無効化

Milkdown(Crepe)が標準で持つ数式(LaTeX)の機能は無効にしている。

- `$テキスト$` と入力しても数式にならない
- テキストを選択すると出るツールバーに、数式のボタンは表示しない
- 実装は `src/components/MarkdownEditor.tsx` で、Crepeの `features` に `[CrepeFeature.Latex]: false` を指定している

# 表のセル内改行

編集モードでは、表のセルの中で改行できる。Markdownファイルの中ではHTMLの `<br>` として保存する(GFMの表はセル内に改行を書けないため)。

- セル内ではShift+Enterで改行する(Enterは表から抜ける操作のまま)
- 表のセル結合には対応していない(GFMの表の範囲で扱う)
- 実装は `src/components/tableBreakPlugin.ts`。読み込み時にセル内の `<br>` `<br/>` `<br />` を改行ノードへ変換し、書き出し時にセル内の改行を `<br>` にする。セルの外の改行は標準の処理のまま
- Milkdown標準の `remark-preserve-empty-line` が `<br>` をすべて取り除くため、読み込みの変換はremarkプラグインの並びの先頭に差し込んでいる(後ろだと `<br>` が消え、保存し直したときにファイルからも失われる)
- Milkdown標準では表の中に改行を入れられないため、`MarkdownEditor.tsx` で `hardbreakFilterNodes` からtableを外している(コードブロックは従来どおり不可)
- Milkdown標準のShift+Enterは、改行の直後にもう一度押すと改行を段落に置き換える。セルは段落を持てないため、表が分割されたりカーソルが表の外へ出たりする。そこでセルの中では、標準より優先するショートカットを `tableBreakPlugin.ts` に用意し、押した回数だけ改行を入れる(セルの外は標準のまま)
- 表示モードでは `rehype-raw` で `<br>` を要素として解釈し、`rehype-sanitize` の既定で許可されているため、追加の設定なしで改行される

# リンクの設定

編集モードでは、リンク設定モーダルでリンクを挿入・変更する。

- テキストを選択すると出るツールバーのリンクボタン、またはMod+Kで、モーダルを開く(標準のリンクボタンの「付け外し」の動作は差し替えている)
- モーダルには「リンク先」と「リンクテキスト」の入力欄がある。初期値は次のとおり
  - カーソルがリンク上: 設定されているURLとリンクテキスト
  - テキスト選択中: どちらも選択中のテキスト(選択を優先する。選択がリンクの内側でも同じ)
  - それ以外: どちらも空欄
- 「リンクを挿入」を押す(Enterキーも同じ)と、カーソルがリンク上ならそのリンク全体、選択中なら選択範囲を、入力したリンクに置き換える。どちらでもなければカーソル位置に挿入する。リンクテキストが空欄のときは、リンク先をリンクテキストにする。置き換え前の先頭の文字の書式(太字など)は引き継ぐ
- リンク先が空欄(空白のみを含む)のときは「リンクを挿入」を押せない。Enterでも挿入されない
- 「キャンセル」、モーダルの外側のクリック、Escキーでモーダルを閉じる。閉じたあとはエディタにフォーカスが戻る
- モーダルでのリンクの解除はできない(次節のリンク解除で行う)
- リンク先の入力中は、文書にあるページやファイルを候補としてドロップダウンに表示し、選んでリンク先に設定できる(インクリメンタルサーチ)。仕様は次のとおり
  - 表示条件は、次のすべてを満たしたとき
    - リンク先を1文字以上入力している(日本語入力の変換中の未確定の文字列は無視し、確定済みの文字列で判断する)
    - リンク先の入力欄またはドロップダウンにフォーカスがある
    - 表示する候補が1つ以上ある
    - 入力されたリンク先に対応するページまたはファイルが実際に存在しない(存在すれば選択済みとみなす)。存在の判定は、現在のページのURLを基準にリンク先を解決してから、Server Action `linkTargetExists` でファイルの有無を調べる。`../` を含む入力も扱える。拡張子なしの `/dir/page` は `/dir/page.md` があれば存在とみなし、Markdown以外は拡張子付きのまま調べる
  - Escで閉じたあと、またはファイルを選んだあとは、次にリンク先を入力するまで表示しない
  - 候補は、ドットで始まるフォルダ・ファイル(`.oreno` を含む)を除く、文書ルート以下のすべてのファイル(Markdown以外も含む)。編集中のページ自身も含む
  - 候補は、次のA〜Cのいずれかに該当するファイル。大文字小文字は区別しない。複数に該当するときは最も優先度の高い条件だけに分類する。ファイル名は拡張子を含み、相対パスは文書ルートからの拡張子付きのパス
    - A: ファイル名が入力中のリンク先から始まる
    - B: 相対パスが入力中のリンク先から始まる
    - C: 相対パスが入力中のリンク先を含む
  - B・Cとの比較では、入力の先頭の `/` を1つ取り除く(リンク先は `/dir/page` の形で入力されることが多いため)
  - 並び順は、A、B、Cの順。同じ条件の中は相対パスの昇順(文字コード順)
  - 各行は、ファイル名の右に、フォルダのパス(文書ルートからの相対。末尾の `/` なし。ルート直下は `.`)を薄い色で並べる。幅に収まらない部分は見切れてよく、省略記号などは付けない
  - 設定されるリンク先は、文書ルートからの絶対形式(`/dir/page`)。Markdownは拡張子を省き、それ以外のファイルは拡張子付き(`/dir/image.png`)
  - ドロップダウンは、リンク先の入力欄の下に隙間なく付ける。高さは20件分までで、収まらないときはスクロールする
  - 下キーで、ドロップダウンにフォーカスが移り、先頭の候補が選択状態になる。上下キーで選択を切り替える。先頭で上キーを押すと入力欄にフォーカスが戻る。末尾で下キーを押しても何も起きない
  - 選択中にSpaceまたはEnterを押すと、そのファイルがリンク先に設定される。候補をクリックしたときは、選択状態にならず、すぐに設定される。どちらも、設定後にドロップダウンが消えて、入力欄にフォーカスが戻る
  - ドロップダウンにフォーカスがあるときのEscは、モーダルを閉じずにドロップダウンだけを閉じて、入力欄にフォーカスを戻す。ドロップダウンにフォーカスがある間は文字を入力できない。Tabキーの移動ではドロップダウンを飛ばす
  - ドロップダウンにフォーカスがあっても、リンク先の入力欄はフォーカスがあるときの見た目のままにする(CSSの `:focus-within` で実現している)。ドロップダウンの輪郭はフォーカスの有無で変えない
  - 候補のファイル一覧は、サーバーが保持している一覧を、モーダルを開いたときにServer Action `getLinkCandidates` で取得する。同時にサーバーへ一覧の更新(スキャン)を依頼するが、完了は待たず、更新前の一覧をそのまま使う。更新が終わるまで1秒ごとに取り直し、終わったら新しい一覧に差し替える。最初のスキャンが終わっていないときは、候補の代わりに「(ファイル一覧を取得中...)」を表示する(選択できない)
  - 候補の絞り込みと並べ替えはクライアントで行う(`src/lib/linkCandidates.ts`)
- ダークモード(OSの設定に従う)では、背景を暗くしたうえでモーダルを一段明るくして枠線を付け、範囲が分かるようにしている
- 実装は `src/components/LinkDialog.tsx`(モーダル本体とドロップダウン)、`linkEdit.ts`(対象範囲の判定と置き換え)、`MarkdownEditor.tsx`(ボタンの差し替えとMod+K)。Crepe標準のリンクツールチップ(リンク上に出る編集・削除の小窓)は、Crepeの `features` に `[CrepeFeature.LinkTooltip]: false` を指定して無効にしている

# リンクの解除

編集モードでは、リンク設定モーダルとは別の操作でリンクを解除する(リンクのテキストは残り、リンクだけが外れる)。

- テキストを選択すると出るツールバーの、リンク設定ボタンの右隣にある「リンク解除」ボタンで、選択した部分のリンクを解除する。リンクの一部だけを選択したときは、その部分だけが解除され、残りはリンクのままになる。複数のリンクにまたがる選択は、選択範囲の中のリンクをすべて解除する
- 選択範囲にリンクがないときは、リンク解除ボタンは薄く表示して押せない状態にする
- 範囲選択なしでカーソルがリンク上にあるときは、リンクの真上にリンク解除ボタンだけを載せた小さなバーを表示する。押すとそのリンク全体を解除する。エディタからフォーカスが外れている間(リンク設定モーダルを開いている間など)は表示しない
- ショートカットは Mod+Alt+K。選択中なら選択した部分、カーソルがリンク上ならそのリンク全体を解除し、リンクがなければ何もしない。Mod+Shift+K にしていないのは、WindowsとLinuxのFirefoxで開発者ツールのコンソールに使われているため。MacのFirefoxではCmd+Option+Kがコンソールに使われているため、Firefoxでは使えないことがある
- ボタンのアイコンは、リンク設定ボタンの図形に右上から左下への斜線を重ねたもの(`src/components/unlinkIcon.ts`)
- 実装は `linkEdit.ts`(解除処理と、カーソルがあるリンクの範囲の判定)、`unlinkButtonPlugin.ts`(カーソルがリンク上にあるときのバー)、`MarkdownEditor.tsx`(ツールバーのボタンとショートカット)。ツールバーのボタンに「押せない状態」はないため、`active` を「解除できるリンクがある」の意味で使い、`active` でないときの見た目は `globals.css` で切り替えている
