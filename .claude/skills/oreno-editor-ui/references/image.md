# 画像の挿入

編集モードでは、画像挿入モーダルで画像を挿入する。Markdownファイルの中では `![代替テキスト](画像パス "タイトル")` として保存する。

- 行頭の＋アイコンで開くメニュー(スラッシュメニュー)の先頭にある「Image」を選ぶと、モーダルが開く。開く前に、メニューを開くために入力した `/` などは消す
- エディタにフォーカスがあるときは、Mod+Pでもモーダルを開く(ブラウザの印刷より優先する)。メニューから開くときと違い、文字は消さずにカーソル位置へ挿入する
- 画像を選択している(画像をクリックして選択状態にしている)ときにMod+Pを押すと、各入力欄が選択中の画像の画像パス・タイトル・代替テキストで初期入力される。このときモーダルのタイトルと実行ボタンは「画像を変更」になり、押すと新しい画像を挿入せずに、選択中の画像を置き換える。初期入力された画像パスの候補のドロップダウンは、画像パスを入力し直すまで表示しない。それ以外のときは、入力欄が空欄の「画像を挿入」になる
- モーダルには「画像パス」「タイトル」「代替テキスト」の入力欄がある。タイトルと代替テキストは空欄でもよい。入力値は常に空欄から始まる
- 「画像を挿入」を押す(Enterキーも同じ)と、カーソル位置に画像を挿入する。段落の途中にも挿入でき、その場合は文の中の画像になる。画像だけの行にしたければ、画像だけの段落にする
- 画像パスが空欄(空白のみを含む)のときは「画像を挿入」を押せない。Enterでも挿入されない
- 「キャンセル」、モーダルの外側のクリック、Escキーでモーダルを閉じる。閉じたあとはエディタにフォーカスが戻る
- 画像パスは入力された文字列をそのまま書き込む(`images/my_image.png` ならそのまま)。Markdownから文書セットの外の画像を参照しても、表示はされない(文書セット内のファイルしか配信しないため)。文書セットの外の画像を使うときは、次の「画像ファイルのドロップ(画像インポート)」で文書セットの中へコピーする
- 画像パスの入力中は、リンク設定モーダルのリンク先と同じ仕組み(候補の絞り込み・並び順・キー操作・存在判定・ファイル一覧の取得。仕様は `link.md` を参照)で、ドロップダウンに候補を表示する。違いは、候補が画像ファイル(拡張子が png, jpg, jpeg, gif, webp, svg, avif, bmp, ico)だけである点と、選んだときに設定されるのが拡張子付きの絶対形式(`/images/my_image.png`)である点
- Crepe標準の画像機能(`CrepeFeature.ImageBlock`)は無効にしている。有効だと、画像が単独の段落にあるときにブロック画像として読み込まれ、保存時に代替テキストがサイズ倍率(`1.00` など)に置き換えられるため。無効にすると、画像は標準の image ノードになり、代替テキストとタイトルがそのまま保存される。副作用として、画像のドラッグによるリサイズと、画像下部のタイトル(キャプション)の表示・編集はできない。スラッシュメニューの標準の「Image」も消えるため、`MarkdownEditor.tsx` の `buildMenu` で自前の項目を足している
- 実装は `src/components/ImageDialog.tsx`(モーダル本体とドロップダウン。見た目は `LinkDialog.module.css` を共用している)と `MarkdownEditor.tsx`(メニュー項目と挿入)

# 画像ファイルのドロップ(画像インポート)

編集モードでは、ファイラー(Windowsのエクスプローラなど)から画像ファイルをエディタにドラッグ&ドロップして、文書セットの外の画像を取り込める(画像インポート)。表示モードではドロップできない。

## ドロップの受け取り

- 画像かどうかは、拡張子(png, jpg, jpeg, gif, webp, svg, avif, bmp, ico。大文字小文字は区別しない)で判定する(`src/lib/imageFile.ts`)。ドロップできるのは単一の画像ファイルだけ。画像以外のファイルや、複数のファイルはドロップできない
- ドロップできないものをエディタの上に持ってきたときは、マウスポインタを禁止マークにして、ドロップ位置の水平線(ドロップカーソル)も出さない(`handleDragOver`)。ドラッグ中はファイル名が分からないため、ファイルが1つで、MIMEタイプが `image/` で始まる(OSによっては空になるので、空も許可する)かどうかで見分ける。MIMEタイプが空のまま拡張子が画像でないファイルは、ドロップ時の拡張子の判定で無視する。Macでは、ポインタが禁止マークにならず、ドロップ可能なときに付く「+」が消えるだけ(ポインタをOSが描くため)
- ドロップしたら、まずサーバーに、画像パスの初期入力などを問い合わせる(`getImageImportContext`)。問い合わせが終わるまでは何も表示せず、終わってからユーザー設定(`image-import.use-modal`。oreno-user-settings スキルを参照)に従って動く。モーダルを開いてから初期入力が書き換わることはない
  - `true`(未設定も同じ): 画像インポートモーダルを開く
  - `false`: モーダルを開かず、確認なしで、初期入力の画像パスにコピーして埋め込む
- コピー(保存)に失敗したときは、画面上部に「画像の保存に失敗しました。」を赤い背景で表示し、文書の保存失敗と同じ3秒で消す。画像は埋め込まない

## 画像パスの初期入力

デフォルトフォルダと、ドロップしたファイルの名前をつないだもの(`/images/photo.png` のような絶対形式)。

- デフォルトフォルダは、ユーザー設定の `image-import.default-folder`。空、未設定のときは、ページのフォルダ
- 同名のファイルがすでにあり、ユーザー設定の `image-import.handle-same-filename` が `append-timestamp` のときは、ファイル名の拡張子の前に、`_` で区切って年月日時分秒のタイムスタンプを付ける(`photo_20261106153045.png`)。タイムスタンプはサーバーのタイムゾーンで作る。付けても重複する場合は考慮しない。`overwrite` のときは何もしない
- 実装は `src/lib/imageImport.ts` の `prepareImageImport`

## 画像インポートモーダル

`src/components/ImageImportDialog.tsx`。見た目は画像挿入モーダルと共用している(`LinkDialog.module.css`。このモーダルだけのスタイルは `ImageImportDialog.module.css`)。

- 構成: タイトル「画像をインポート」、「画像パス」「タイトル」「代替テキスト」の入力欄(プレースホルダーは画像挿入モーダルと同じ)、画像パスの右の画像フォルダ選択ボタン、「キャンセル」「画像をインポート」ボタン。開いたら画像パスにフォーカスする
- 画像パスは、絶対形式(`/images/a.png`)と、ページのフォルダからの相対(`images/a.png`、`../a.png`)のどちらも入力できる。入力した画像パスを、コピー先と、Markdownに書く画像パスの両方に使う。Markdownに書くときは、パスの中の各名前のうちASCIIの記号(空白、%、(、) など)だけをURLエンコードし、日本語などのASCII以外の文字はエンコードしない(/docs/画像 1.png → /docs/画像%201.png。encodeImageSrc)
- 使えない画像パスのときは、入力欄の下に赤いメッセージを出し、「画像をインポート」を押せなくする。空欄のときはメッセージは出さず、押せなくするだけ。判定は `resolveImagePath`(`src/lib/imagePath.ts`)で、サーバー側でも同じ判定をやり直す
  - 空の名前を含む(`//`): 「画像パスの形式が正しくありません。」
  - `.` から始まる名前を含む: 「「.」から始まる名前は使えません。」
  - 文書セットの外を指す(`..` で文書ルートより上に出る): 「文書セットの外は指定できません。」
  - `:` や `[` などURLのセグメントとして許可しない文字を含む: 「使えない文字が含まれています。」
  - 画像の拡張子で終わらない(拡張子なしを含む): 「画像ファイルの拡張子（.png など）が必要です。」
- 入力した画像パスにすでにファイルがあるときは、入力欄の下に黄色で「同じパスにファイルがあります」を表示する。入力のたびにサーバーへ問い合わせて判定する(`checkImageFileExists`。ファイルインデックスは使わない)。エラーがあるときはエラーだけを表示する
- 画像パスの入力中は、フォルダの候補だけをドロップダウンに表示する(画像ファイルは出さない)。最後の `/` より前をフォルダとみなして絞り込み(リンク先と同じ規則)、候補を選ぶと、ファイル名の部分は残して、フォルダ部分だけを置き換える(`FolderPathInput` の `withFileName`)
- 画像フォルダ選択ボタン(フォルダのアイコン)を押すと、下にフォルダの一覧が開く。1つ目は「（ページのフォルダ）」、2つ目以降はプロジェクト設定の画像フォルダ一覧(`image-folders`。oreno-project-settings スキルを参照)。選ぶと、画像パスのファイル名より前を、そのフォルダのフルパスに置き換える。Escキーかフォーカスが外れたときは、モーダルを閉じずにメニューだけ閉じる
- 「画像をインポート」を押す(Enterも同じ)と、画像ファイルを入力された画像パスにコピーして、ドロップした位置に埋め込む。タイトルと代替テキストは入力した値(空欄でもよい)。押した時点でもう一度ファイルの有無を問い合わせ、すでにあるときは `confirm` で「すでに同じパスにファイルがあります。上書きしますか？」と確認する。キャンセルされたら、何もせずモーダルを表示したままにする
- コピー中は「画像をインポート」を押せない。コピーが終わったら(失敗したときも)モーダルを閉じる
- 「キャンセル」、モーダルの外側のクリック、Escキーで閉じると、コピーも埋め込みもしない。閉じたあとはエディタにフォーカスが戻る

## コピーと埋め込み

- 画像ファイルは、「画像をインポート」を押すまでブラウザのメモリに持っておく。ドロップ位置も、サーバーへの問い合わせとモーダルの操作でカーソルが動いてもずれないよう、ドロップ時に求めて控えておく
- 保存先のフォルダがなければ作る。ページがまだ保存されていない新規作成中でも、保存先は決まっているので、そのまま保存する。そのあとページを保存しなければ、参照されない画像が残るが、許容する
- 保存先に同名のファイルがあるときは上書きする(確認は上のとおり、モーダルを開いたときは押した時点、開かないときは確認なし)。その画像を参照している別のページの表示も変わる
- ドロップした位置に画像を埋め込む。段落の途中にドロップしたときは、既存の画像挿入と同じく文中の画像になる
- サイズ上限は設けない。そのため、Server Action(ボディサイズの上限がある)ではなく Route Handler(`src/app/.oreno/upload_images/route.ts`)で保存する。リクエストは `slug`(ページの slug)、`file`(画像ファイル)、`path`(保存先の画像パス)を持つ
- 保存した画像は、すぐにファイルインデックスへ反映する(`registerAttachmentFile`。仕様は oreno-file-index スキルを参照)。画像パスの候補にすぐ出る
- 実装は `MarkdownEditor.tsx` の `handleDrop`(ドロップの受け取り)、`startImport`(問い合わせと分岐)、`importImage`(コピーと埋め込み)と、`DocumentPage.tsx` の通知
