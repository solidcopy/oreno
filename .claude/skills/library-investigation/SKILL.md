ライブラリ、フレームワーク、SDK、外部APIの仕様を確認する必要がある場合は、Context7 MCPを使用して公式ドキュメントを参照する。

特に、未知のAPIの使用、ライブラリの導入、設定変更、バージョンアップ、API仕様が不明確な場合は、実装前にContext7で確認する。

ドキュメントの取得時は、使用バージョンを確認し、そのバージョンに対応するドキュメントを優先する。
バージョンは `package.json` の該当ライブラリの行だけを確認する（grepなどで絞り、ロックファイルは全体を読まない）。

既存コードや直近に取得したドキュメントから仕様が十分に確認できる場合は、Context7への重複した問い合わせを避ける。

変数名変更、単純なリファクタリング、プロジェクト固有のロジック変更など、外部ドキュメントを必要としない作業ではContext7を使用しない。

Context7からは、現在の作業に必要なAPIや機能の情報のみを取得する。ライブラリ全体のドキュメントを無差別に取得しない。

`query-docs` のクエリは、具体的なAPI名や機能名を含む1つの話題に絞る（「routing and auth」のように複数の話題を1回にまとめない）。
取得結果は必要な部分だけを作業に使い、ドキュメントやコード例を全文再掲しない。

Context7の呼び出しは、1つの調査課題につき `resolve-library-id` と `query-docs` を各1回とすることを基本にする。
追加で呼び出す場合も、同じ課題につき合計3回までとする。
一度解決したライブラリIDは再利用し、同じライブラリに対して `resolve-library-id` を繰り返さない。

このプロジェクトの主要ライブラリは、次のIDを `query-docs` に直接渡してよい（`resolve-library-id` は不要）。

| ライブラリ | ライブラリID | 備考 |
|---|---|---|
| Next.js | `/vercel/next.js/v16.2.9` | プロジェクトは16.3.5だが、Context7にあるのは16.2.9まで。最新が必要なら `/vercel/next.js` |
| React | `/websites/react_dev` | React 19の公式ドキュメント |
| Milkdown | `/websites/milkdown_dev` | 公式サイトのドキュメント。`@milkdown/crepe` もこちらで調べる |

上記以外のライブラリは、`resolve-library-id` で解決する。

上限の範囲で適切なドキュメントを取得できない場合は、クエリを変えて再試行し続けず、他の信頼できる情報源を利用する。
未確認の仕様を推測だけで実装しない。
